## 1 欢迎与概述

**本章你将学会：** 波笛智能体是什么、能做什么，以及你即将接触的核心概念。

### 1.1 什么是波笛智能体

波笛智能体（BodiAgentTeam）是一个面向 AI 原生团队的协同工作平台。它将传统的项目管理（看板、Issue、项目）与 AI 智能体（Agent）深度融合，让团队成员和 AI 智能体在同一平台上协作。

简单说：**你可以把任务分配给 AI，就像分配给同事一样自然。**

### 1.2 核心概念

| 概念 | 说明 |
|------|------|
| **Issue** | 工作项 / 任务，类似其他平台中的"工单"或"卡片"，支持分配、评论、标签、优先级 |
| **Agent（智能体）** | AI 工作单元，每个 Agent 绑定一个 AI 模型（如 Claude、Codex），可被分配任务并自动执行 |
| **Workspace（工作区）** | 团队协作空间，工作区之间数据完全隔离 |
| **Project（项目）** | Issue 的分组集合，用于组织和管理相关任务 |
| **看板（Kanban）** | 按状态分列的卡片视图，支持拖拽变更 Issue 状态 |
| **Daemon（守护进程）** | 安装在开发机上的后台程序，负责接收和执行 Agent 任务 |
| **Autopilot（自动化）** | 按计划自动创建 Issue 并分派给 Agent 的自动化规则 |
| **Chat（聊天会话）** | 与 Agent 进行实时对话式交互的功能，支持创建会话、发送消息和接收 Agent 回复 |

### 1.3 适用场景

- 使用 AI 辅助开发的软件团队
- 需要将 AI 作为"数字员工"参与工作流的团队
- 探索 AI 原生开发流程的前沿团队

## 2 快速入门

**本章你将学会：** 从注册账号到创建第一个 Issue 的完整流程。

### 2.1 注册账号

**做什么：** 创建波笛智能体账号。

**方式一：邮箱密码注册**

1. 在浏览器中打开波笛智能体系统地址（由管理员提供）。
2. 点击登录页面的**注册**链接，进入注册页面。
3. 填写以下信息：
   - **姓名**：你的显示名称（如"张三"）。
   - **邮箱地址**：用于登录和接收通知。
   - **密码**：至少 8 位，包含字母和数字。
   - **确认密码**：再次输入密码。
4. 点击**注册**按钮。

**预期结果：** 注册成功，系统自动登录并跳转到工作台页面。你将看到"你好，[你的姓名]"的欢迎信息。

**方式二：验证码登录**

系统还支持通过邮箱验证码直接登录（无需提前注册密码）：

1. 调用 `POST /auth/send-code` 接口，发送 6 位验证码到你的邮箱。
2. 调用 `POST /auth/verify-code` 接口，提交验证码。系统会自动查找已有用户或创建新用户，并返回 JWT 令牌。

> 以上两种方式相互独立：注册使用邮箱 + 密码，验证码登录无需密码。开发环境中验证码固定为 `888888`，生产环境会发送到你的邮箱。

### 2.2 首次登录

**做什么：** 使用注册的账号登录系统。

**操作步骤：**

1. 在浏览器中打开系统地址。
2. 输入邮箱地址和密码。
3. 点击**登录**按钮。

**预期结果：** 登录成功，进入工作台（Dashboard）页面。

> 如果忘记密码，请联系管理员重置（当前版本暂未提供自助找回密码功能）。

### 2.3 创建工作区

**做什么：** 创建你的第一个团队工作区。

> **注意：** 工作区管理功能当前通过 API 操作，Web UI 正在开发中。

**操作方式（通过 API）：**

调用 `POST /api/workspaces/`，提交以下信息：
- **名称**：如"产品研发团队"。
- **Slug**：工作区标识符，用于 URL，如 `product-team`。
- **Issue 前缀**：Issue 编号前缀，如 `BOD`（生成格式如 `BOD-001`、`BOD-002`）。
- **描述**：简短介绍工作区的用途（可选）。

**预期结果：** 工作区创建成功。你是该工作区的 **Owner（拥有者）**，拥有全部管理权限。现在可以开始使用看板和智能体功能了。

### 2.4 邀请团队成员

**做什么：** 邀请同事加入工作区。

> **注意：** 团队成员邀请功能当前通过 API 操作，Web UI 正在开发中。

**操作方式（通过 API）：**

调用 `POST /api/workspaces/{id}/members/`，提交以下信息：
- **邮箱地址**：对方的邮箱。
- **角色**：
  - **Admin**：管理员，可管理工作区设置和成员。
  - **Member**：普通成员，可使用看板和分配任务。

**预期结果：** 系统创建邀请记录。受邀者登录后可在收件箱中看到邀请通知，点击"接受"即可加入工作区。

> 邀请有效期为 7 天，过期后需重新邀请。

### 2.5 创建第一个 Issue

**做什么：** 在看板上创建一个任务卡片。

**操作步骤：**

1. 在左侧边栏中点击**看板**。
2. 在看板页面右上角点击**新建 Issue** 按钮。
3. 在弹窗中填写：
   - **标题**：简明扼要的标题，如"优化用户登录页面加载速度"。
   - **描述**：详细说明任务内容（支持 Markdown 格式）。
   - **优先级**：紧急 / 高 / 中 / 低。
   - **负责人**：可选，可以分配给团队成员或智能体（Agent）。
   - **项目**：可选，归类到某个项目下。
4. 点击**提交**。

**预期结果：** Issue 创建成功，出现在看板的对应状态列中。

> 每个 Issue 自动获得一个唯一编号，格式为 `[前缀]-[序号]`，如 `BOD-001`。创建者默认为你本人。

### 2.6 基础工作流体验

一个典型的日常流程：

1. 在**看板**中查看待处理的任务。
2. 打开一个 Issue，查看详情、添加评论。
3. 完成任务后，在详情页中将状态改为"已完成"。
4. 在**收件箱**中查看团队成员和智能体的最新动态。

## 3 工作区管理

**本章你将学会：** 管理你的工作区、成员角色和权限。

> **注意：** 本章所述工作区管理操作（编辑、成员管理、退出、删除）当前通过 API 完成，Web UI 正在完善中。各节末尾标注了对应的 API 端点。

### 3.1 工作区角色

每个工作区有三种角色：

| 角色 | 权限 |
|------|------|
| **Owner（拥有者）** | 全部权限，包括删除工作区、转让拥有权 |
| **Admin（管理员）** | 管理成员、邀请、修改工作区设置 |
| **Member（成员）** | 创建和编辑 Issue、使用看板、使用智能体 |

### 3.2 编辑工作区

**做什么：** 修改工作区的名称、描述等基本信息。

> 通过 API 操作：`PATCH /api/workspaces/{id}/`，修改名称、描述、Issue 前缀等信息。

### 3.3 管理成员

**做什么：** 查看、修改成员角色或移除成员。

> 通过 API 操作：
> - 查看成员列表：`GET /api/workspaces/{id}/members/`
> - 修改成员角色：`PATCH /api/workspaces/{id}/members/{member_id}/`
> - 移除成员：`DELETE /api/workspaces/{id}/members/{member_id}/`

> 当前支持修改的角色为 Admin 和 Member。Owner 角色不在此处管理。

### 3.4 退出工作区

**做什么：** 离开某个工作区。

> 通过 API 操作：`DELETE /api/workspaces/{id}/members/me/`

> 如果你是唯一的 Owner，则无法退出工作区。需要先转让 Owner 身份给其他成员，或邀请一个新的 Owner。

### 3.5 删除工作区

**做什么：** 永久删除工作区和所有数据。

> 通过 API 操作：`DELETE /api/workspaces/{id}/`（仅 Owner 可执行）

> **警告：** 删除操作不可恢复，所有 Issue、项目、智能体配置、收件箱记录等数据将永久丢失。

## 4 Issue 管理

**本章你将学会：** 创建、分配、查看、评论、标记 Issue 的全流程操作。

### 4.1 Issue 状态说明

每个 Issue 有 7 种状态，对应看板上的不同列：

| 状态 | 看板列颜色 | 含义 |
|------|-----------|------|
| **Backlog（待规划）** | 灰色 | 尚未排期的想法或任务 |
| **Todo（待处理）** | 蓝色 | 已排期，等待开始 |
| **In Progress（进行中）** | 黄色 | 正在处理 |
| **In Review（审查中）** | 紫色 | 已完成，等待审核 |
| **Done（已完成）** | 绿色 | 已完成 |
| **Blocked（阻塞）** | 红色 | 因依赖项等问题被阻塞 |
| **Cancelled（已取消）** | — | 已取消，不再执行 |

### 4.2 优先级说明

| 优先级 | 含义 |
|--------|------|
| **Urgent（紧急）** | 需要立即处理 |
| **High（高）** | 重要，应尽快处理 |
| **Medium（中）** | 常规优先级 |
| **Low（低）** | 低优先级，有时间再处理 |
| **None（无）** | 未设置优先级 |

### 4.3 查看看板

**做什么：** 在工作区的看板中浏览所有 Issue。

**页面布局说明：**

看板页面采用 5 列水平布局（视口不足时横向滚动）：

- 页面上方是标题栏，左侧显示"Issue 看板"标题及"拖拽卡片以更改状态"提示，右侧是"新建 Issue"按钮。
- 下方是 5 个看板列，从左到右依次为：**待规划、待处理、进行中、审查中、已完成**。
- 每列顶部显示状态名称和该列的卡片数量。
- 每列中显示该状态的 Issue 卡片，卡片上包含编号、标题、优先级标签和更新时间。
- 右上角提供**新建 Issue**按钮，可打开快速创建弹窗。

**操作步骤：**

1. 点击左侧边栏的**看板**。
2. 系统自动加载各个状态列中的 Issue。
3. 点击任意 Issue 卡片，进入详情页查看完整信息。

> 看板通过页面内 JavaScript 请求 API 并渲染卡片，避免把接口 JSON 直接显示到页面。阻塞（Blocked）和已取消（Cancelled）状态的 Issue 默认不显示在看板主列中，可在 Issue 详情或通过其他筛选方式查看。

### 4.4 创建 Issue

**方法一：常规创建**

1. 在看板页面右上角点击**新建 Issue** 按钮。
2. 填写标题（必填）、描述、优先级、负责人、项目等信息。
3. 点击**提交**。

**方法二：快速创建**

1. 点击看板右上角的**新建 Issue**，或通过带 `quick_create=1` 的看板入口打开快速创建弹窗。
2. 填写标题、描述、状态和优先级。
3. 点击**提交**。

**预期结果：** 弹窗关闭，新 Issue 出现在所选状态列中；点击卡片可进入详情页。

### 4.5 查看 Issue 详情

**做什么：** 查看 Issue 的完整信息、评论和活动历史。

**页面布局说明：**

Issue 详情页分为左右两部分：

- **左侧（主区域）：**
  - 顶部：Issue 标题、描述内容。
  - 中部：评论区域，显示所有评论列表，支持 Markdown 渲染。
  - 底部：评论输入框，支持 Markdown。
  - 再下方：活动时间线，展示所有状态变更、分配记录等。

- **右侧（属性面板）：**
  - 状态下拉框
  - 优先级下拉框
  - 负责人下拉框
  - 项目下拉框
  - 截止日期选择器
  - 标签区域
  - 创建时间和更新时间

### 4.6 编辑 Issue

**做什么：** 修改 Issue 的标题、描述等属性。

**操作步骤：**

1. 进入 Issue 详情页。
2. 在右侧属性面板中，直接修改：
   - **状态**：从下拉框选择新状态。
   - **优先级**：从下拉框选择。
   - **负责人**：选择团队成员或智能体。
   - **项目**：选择所属项目。
   - **截止日期**：选择日期。
   - **标签**：添加或移除标签。

标题、描述等主内容通过对应保存按钮提交；状态、优先级、截止日期等属性在右侧面板中修改后即时保存或按页面提示保存。保存后刷新页面仍会保留修改结果。

### 4.7 添加评论

**做什么：** 在 Issue 下发表评论。

**操作步骤：**

1. 进入 Issue 详情页。
2. 在"评论"区域的文本框中输入内容（支持 Markdown 格式）。
3. 点击**发表评论**按钮。

**预期结果：** 评论出现在 Issue 评论列表中，所有订阅该 Issue 的成员和智能体将收到通知。

> 首次加载评论列表时，系统会自动请求 `/api/issues/{issue_id}/comments/` 接口获取数据。发表评论通过 `hx-post` 提交表单。

### 4.8 分配负责人

**做什么：** 将 Issue 分配给团队成员或智能体。

**操作步骤：**

1. 在 Issue 详情页的右侧属性面板中，找到"负责人"下拉框。
2. 从下拉列表中选择一个成员或智能体。
3. 选择后即时生效。

**预期结果：** Issue 的负责人被更新。被分配的成员会在收件箱中收到"分配给我"的通知。如果分配给智能体，智能体将自动开始执行任务（需满足配置条件）。

> 分配对象分为两种类型：**Member（团队成员）** 和 **Agent（智能体）**。系统中使用 `assignee_type` 字段区分。

### 4.9 标签管理

**做什么：** 为 Issue 添加标签进行分类。

**创建标签：**

> 通过 API 操作：`POST /api/labels/`，提交标签名称（如 `bug`、`feature`）和颜色。
> 查看已有标签：`GET /api/labels/`

**为 Issue 添加标签：**

1. 在 Issue 详情页的标签区域，点击**添加标签**。
2. 从下拉列表中选择已有标签。
3. 标签即时出现在 Issue 上。

### 4.10 批量操作

**做什么：** 同时修改多个 Issue 的属性。

**操作说明：**

看板支持批量更新操作，通过 API 的 `batch-update` 端点实现，可同时更新多个 Issue 的：
- 状态
- 优先级
- 负责人
- 所属项目
- 截止日期

具体操作以界面实际提供的批量选择功能为准。

### 4.11 子任务（父子 Issue）

**做什么：** 将一个大型任务拆解为多个子任务。

**操作说明：**

一个 Issue 可以作为另一个 Issue 的**子任务**（通过 `parent_issue` 字段关联）。这样可以将复杂任务分解为更小、更易管理的工作单元。

在 Issue 详情中，可以看到关联的子 Issue 列表。

### 4.12 Issue 依赖

**做什么：** 声明 Issue 之间的依赖关系。

**操作说明：**

Issue 之间可以建立三种依赖关系：
- **Blocks（阻塞）**：当前 Issue 阻塞其他 Issue 的进行。
- **Blocked By（被阻塞）**：当前 Issue 被其他 Issue 阻塞。
- **Related（关联）**：两个 Issue 之间存在关联关系。

在 Issue 详情页可通过相关接口为 Issue 添加依赖关系。

## 5 Agent 管理

**本章你将学会：** 创建、配置、使用 AI 智能体的完整操作。

### 5.1 什么是 Agent

Agent（智能体）是波笛智能体的核心能力。每个 Agent 绑定一个 AI 模型（如 Claude、Codex、Gemini 等），可以被分配 Issue 并自动执行任务。Agent 通过安装在开发机上的 Daemon（守护进程）执行实际工作。

### 5.2 支持的 AI 提供商

系统支持以下 AI 提供商（Provider）：

| 提供商 | 说明 |
|--------|------|
| **Claude** | Anthropic Claude（claude CLI） |
| **Codex** | OpenAI Codex CLI |
| **Copilot** | GitHub Copilot CLI |
| **Gemini** | Google Gemini CLI |
| **OpenClaw** | OpenClaw CLI |
| **OpenCode** | OpenCode CLI |
| **Hermes** | Hermes CLI |
| **Pi** | Pi CLI |
| **Cursor** | Cursor CLI |
| **Kimi** | Kimi CLI |
| **Kiro** | Kiro CLI |

### 5.3 创建 Agent

**做什么：** 创建一个新的 AI 智能体。

**操作步骤：**

1. 在左侧边栏中点击**智能体**，进入智能体列表页面。
2. 页面右上角点击**创建智能体**按钮。
3. 在弹出的表单中填写：
   - **名称**：给智能体取一个容易识别的名字，如"前端助手"。
   - **描述**：简短描述智能体的职责，如"负责前端代码审查和测试"。
   - **提供商**：选择 AI 提供商（如 Claude）。
   - **模型**：输入具体模型名称，如 `claude-sonnet-4-20250514`。
   - **指令（Instructions）**：系统指令，定义智能体的行为和边界（可选）。
4. 点击**创建**。

**预期结果：** 创建成功，智能体卡片出现在列表中。新创建的智能体状态为 **Active（活跃）**，可以接受任务。

> 创建 Agent 前，需要确保至少有一个 Daemon 已注册并在线。Agent 会自动绑定到可用的 Daemon。

### 5.4 Agent 列表

**页面布局说明：**

智能体列表页面采用卡片网格布局：

- 页面上方是标题栏，左侧显示"智能体"标题和"管理工作区内的 AI 智能体"说明，右侧是"创建智能体"按钮。
- 主体区域使用三列网格（响应式）展示每个智能体卡片。
- 每张卡片包含：智能体名称首字母图标、名称、提供商/模型、状态标签（活跃/已归档）、描述文字、最大并发数和创建时间。
- 点击卡片可查看或编辑智能体详情。

### 5.5 配置 Agent 指令

**做什么：** 设置或修改智能体的系统指令，定义其行为准则。

**操作步骤：**

1. 在智能体列表中找到目标 Agent。
2. 点击**编辑**。
3. 在“指令”文本框中更新系统指令，例如：

```
你是一个专业的前端开发助手。你的职责包括：
1. 编写和审查 TypeScript/React 代码
2. 确保代码符合团队规范
3. 编写相关测试
4. 提供性能优化建议

请始终在发表评论前确认你的工作成果。
```

4. 点击**保存**。

> 指令（Instructions）作为 Agent 的系统提示词，会在每次任务执行时传递。精心编写的指令可以显著提升任务执行质量。

### 5.6 管理 Agent 技能

**做什么：** 为 Agent 绑定技能，增强其特定领域能力。

> **注意：** 技能管理功能当前通过 API 操作，Web UI 正在开发中。

**操作方式（通过 API）：**
- 查看 Agent 已绑定技能：`GET /api/agents/{id}/skills/`
- 为 Agent 绑定技能：`PUT /api/agents/{id}/skills/`
- 移除 Agent 技能：在绑定接口中更新技能列表

**什么是技能（Skill）：**

技能是可复用的知识片段，包含文本内容和文件。一个技能可以包含：
- 描述性文本（指导 Agent 如何完成某类任务）
- 参考代码或模板文件

> Agent 的技能以多对多关系关联。一个 Agent 可以绑定多个技能，一个技能也可以被多个 Agent 使用。

### 5.7 创建技能

**做什么：** 编写和导入新的技能。

> 通过 API 操作：
> - 创建技能：`POST /api/skills/`，提交名称、描述、内容（Markdown 格式）和可选文件
> - 查看技能列表：`GET /api/skills/`

### 5.8 归档和恢复 Agent

**归档 Agent：**

1. 在智能体列表中找到目标 Agent。
2. 点击卡片上的**归档**。
3. 确认归档。

归档后的 Agent 不再接收新任务。其状态标签变为"已归档"。

**恢复 Agent：**

1. 在智能体列表的筛选条件中选择"已归档"。
2. 找到目标 Agent。
3. 点击**恢复**。
4. Agent 状态恢复为"活跃"。

### 5.9 取消 Agent 的待处理任务

**做什么：** 取消某个 Agent 当前排队或执行中的所有任务。

**操作步骤：**

1. 在智能体列表中，点击目标 Agent 卡片。
2. 在详情中找到并使用**取消任务**功能。
3. 确认取消。

**预期结果：** Agent 下所有处于"排队中"、"已派发"和"运行中"状态的任务被统一标记为"已取消"。

### 5.10 查看 Agent 任务历史

**做什么：** 查看 Agent 曾经执行过的所有任务。

**操作步骤：**

1. 在智能体列表中找到目标 Agent。
2. 在详情页中查看任务列表。
3. 任务按时间倒序排列，显示每个任务的状态、关联 Issue 和创建时间。

## 9 自动化（Autopilot）

**本章你将学会：** 配置自动化规则，让系统按计划自动创建 Issue 并分派给智能体。

Autopilot 已提供 Web 管理页面，可在左侧边栏点击**自动驾驶**进入。

### 9.1 什么是 Autopilot

Autopilot（自动化调度）是系统的定时任务引擎。你可以配置一个自动化规则：

- **定时触发**：按 cron 表达式（如每天早上 9 点）自动执行。
- **Webhook 触发**：通过外部 Webhook 调用触发。
- **API 触发**：通过 API 调用触发。

触发后，Autopilot 可以：
1. **创建 Issue**（`create_issue` 模式）：按模板自动创建一个 Issue。
2. **运行任务**（`run_only` 模式）：直接为指定 Agent 创建一个任务。

### 9.2 创建 Autopilot

**做什么：** 创建一个自动化规则。

1. 进入**自动驾驶**页面。
2. 选择一个模板（如**每日摘要**），或点击创建入口打开表单。
3. 填写标题、触发标签、频率/Cron 配置，并选择负责执行的 Agent。
4. 点击**保存**。

**预期结果：** Autopilot 出现在列表中，默认处于启用状态。你可以继续编辑 Cron、暂停、启用或删除。

### 9.3 Cron 表达式示例

| 描述 | Cron 表达式 |
|------|-------------|
| 每天早上 9 点 | `0 9 * * *` |
| 每工作日早 9 点 | `0 9 * * 1-5` |
| 每周一上午 10 点 | `0 10 * * 1` |
| 每小时 | `0 * * * *` |
| 每 30 分钟 | `*/30 * * * *` |

### 9.4 手动触发 Autopilot

**做什么：** 即使未到定时时间，也可以手动触发一次自动化。

在自动驾驶列表中点击目标规则的**触发**按钮即可手动执行一次。系统会创建运行记录；运行记录仅在手动触发后刷新显示，避免列表刷新时产生无效请求。

### 9.5 查看执行记录

**做什么：** 查看 Autopilot 的历史执行情况。

在自动驾驶列表中查看目标规则的运行记录区域，可看到每次触发的运行状态：
> - Issue Created（已创建 Issue）
> - Running（运行中）
> - Completed（已完成）
> - Failed（失败）
> - Skipped（已跳过）

### 9.6 暂停 / 启用 Autopilot

在自动驾驶列表中点击**暂停**或**启用**即可切换状态。暂停后触发器不再执行；启用后恢复执行。

### 9.7 删除 Autopilot

**做什么：** 删除不再需要的自动化规则。

在自动驾驶列表中点击**删除**并确认。

> 删除后历史运行记录也会被删除。

## 11 常见问题 FAQ

**本章你将学会：** 回答日常使用中可能遇到的问题。

### 11.1 账号与登录

**Q：我忘记了密码，如何重置？**

A：当前版本暂未提供自助找回密码功能。请联系系统管理员在后台为你重置密码。

**Q：我可以注册多个账号吗？**

A：系统使用邮箱作为唯一标识，一个邮箱只能注册一个账号。但一个用户可以加入多个工作区。

**Q：如何修改登录邮箱？**

A：当前设置页面中的邮箱为只读展示。如需修改登录邮箱，请联系管理员或通过后续账号管理功能处理。

### 11.2 工作区

**Q：我可以创建多少个工作区？**

A：没有数量限制。你可以在设置中创建任意数量的工作区，每个工作区的数据完全隔离。

**Q：如何切换工作区？**

A：侧边栏顶部显示当前工作区名称（当前为纯文本显示，工作区切换功能正在开发中）。

**Q：工作区删除后数据能恢复吗？**

A：不能。删除工作区会永久删除所有相关数据（包括 Issue、项目、智能体配置等），请谨慎操作。

### 11.3 Issue

**Q：Issue 编号的格式是什么？**

A：格式为 `[前缀]-[序号]`，如 `BOD-001`、`BOD-002`。前缀在工作区创建时设置，序号按创建顺序递增。

**Q：如何给 Issue 设置负责人？**

A：在 Issue 详情页的右侧属性面板中，从"负责人"下拉框选择人员或智能体。

**Q：评论支持什么格式？**

A：评论支持 Markdown 格式，可以使用标题、列表、代码块、链接等。

**Q：如何删除一个 Issue？**

A：在 Issue 详情页中可以使用删除功能（由管理员或创建者操作）。

### 11.4 智能体

**Q：为什么创建了 Agent 但它不执行任务？**

A：可能的原因：
1. 没有安装并启动 Daemon CLI。
2. Daemon 未在线（在设置页确认 Daemon 状态）。
3. 没有将 Issue 分配给该 Agent。
4. Agent 的并发任务数已达上限（`max_concurrent_tasks`）。

**Q：Agent 有不同的提供商，我应该选哪个？**

A：根据你的开发环境选择已安装的 AI CLI 工具。常用选择：
- Claude：成熟的代码生成能力
- Codex：OpenAI 模型
- Gemini：Google 模型
其他选项根据实际可用性选择。

**Q：Agent 执行任务时我能看到进度吗？**

A：可以。在 Issue 详情页的活动时间线中，可以实时看到 Agent 的进度更新，包括思考过程、工具调用和代码变更等。

**Q：如何删除一个 Agent？**

A：在智能体列表中可以对 Agent 执行删除操作，或先归档再删除。

### 11.5 自动化

**Q：Autopilot 支持哪些触发方式？**

A：支持三种触发方式：定时（Cron 表达式）、Webhook 调用、API 调用。

**Q：Autopilot 执行失败怎么办？**

A：查看执行记录中的失败原因。常见原因包括 Agent 不可用、Issue 创建失败等。修复后可以手动重新触发。

### 11.6 其他

**Q：系统支持深色模式吗？**

A：是的。在设置页面的偏好设置中可以选择浅色、深色或跟随系统主题。

**Q：数据存储在什么地方？**

A：使用 PostgreSQL 数据库存储所有业务数据，使用 Redis 作为消息队列。文件附件存储在本地文件系统或配置的云存储（如阿里云 OSS）。

**Q：如何联系技术支持？**

A：请联系你的系统管理员或团队负责部署的技术人员。
