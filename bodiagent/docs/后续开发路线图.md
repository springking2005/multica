**现状**：`chat/consumers.py` 中 `ChatConsumer` 已实现完整的 WebSocket 逻辑，但 `bodiagent/asgi.py` 的 `URLRouter` 为空——未注册任何消费者路由。Chat UI 的前端开发和 daemon WebSocket 控制面均依赖此步骤。

**需完成**：

| 任务 | 说明 | 预计工作量 |
|------|------|-----------|

| WebSocket smoke test | 编写连接/发送/接收测试，确认 `/ws/chat/{session_id}` 可用 | **0.5 人天** |
| 确认 DaemonConsumer 状态 | DaemonConsumer 当前为桩，明确是否需在 Phase 0 实现或延后 | **0.25 人天** |

**验收标准**：

## 风险提示

1. **daemon_cli 端到端最大的不确定因素**是 AI CLI 的实际输出格式和错误处理——不同版本（Claude Code / Codex CLI）输出格式可能变化，需要增加格式解析的健壮性。
2. **前端工作量可能被低估**——Django Templates + HTMX 方案在处理复杂交互（如 Chat 流式输出、看板拖拽）时有天然局限，未来可能需要引入轻量前端框架（Alpine.js / htmx 扩展），应在 P2.2 阶段评估技术方案升级。
3. **PostgreSQL 迁移**最可能的坑是 SQLite 特有的字段行为（如 JSONField 查询、大小写不敏感 LIKE），需要逐 app 测试。
4. **文件存储**切换时需要处理已有本地文件的迁移（如果有的话），建议投产前完成。
5. **i18n** 在 Django Templates 方案下比较成熟，但若未来前端方案变更为 SPA，需要重新设计国际化方案。
