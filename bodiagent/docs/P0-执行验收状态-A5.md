- 缩小复现：`python3 -m pytest -q chat/tests/test_websocket.py e2e/specs/test_chat_ui.py -n auto` 可触发混跑失败。

### 根因结论

- 原 ASGI 浏览器 fixture 使用 `channels.testing.live.DaphneProcess` 在 pytest/Playwright 已运行的进程中 fork Daphne。
- 当 Channels communicator 异步测试与 Playwright 同一 pytest 进程/worker 混跑时，fork 方案会继承或污染 asyncio / Channels 运行时状态，导致浏览器 WebSocket 连接被服务端断开。
- 这不是 Chat UI 业务逻辑失败；是测试 harness 进程模型与 async/browser 混跑不隔离导致的。

### 已完成修复

- 新增 `e2e/asgi.py`：专用 Playwright ASGI entrypoint，在 Daphne 子进程内：
  - 指向 pytest 当前 worker 的 file-backed SQLite 测试库；
  - 使用 signed-cookie session；
  - 重建 ASGI app、静态文件 wrapper、Channels URLRouter；
  - 清空 channel layer cache，避免复用父进程状态。
- 重写 `e2e/conftest.py` 的 `asgi_live_server`：
  - 不再使用 `DaphneProcess` fork；
  - 改为 `subprocess.Popen([python, -m, daphne, ...])` 启动独立 Daphne 进程；
  - 动态端口、`/health/` readiness、日志捕获、超时失败显式报错；
  - teardown 时 terminate/kill 并关闭日志句柄。
