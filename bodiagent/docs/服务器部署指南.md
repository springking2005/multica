# BodiAgent 服务器部署指南

更新日期：2026-05-17  
适用分支：`feature/zh-cn`  
部署方式：Docker Compose 优先；宿主机 Python 运行作为排障/临时方案。

---

## 1. 服务器规格建议

| 场景 | CPU | 内存 | 磁盘 | 说明 |
|------|-----|------|------|------|
| 最小测试/演示 | 2 vCPU | 4 GB | 40 GB SSD | 仅适合短期验证，余量小 |
| 小团队生产推荐 | 4 vCPU | 8 GB | 80-100 GB SSD | Web + PostgreSQL + Redis 同机起步配置 |
| 稳妥生产推荐 | 4 vCPU | 16 GB | 100-200 GB SSD | 推荐配置，适合同时运行少量 daemon/Agent |
| 中等团队/多 Agent | 8 vCPU | 32 GB | 200 GB+ SSD | 多用户、多任务并发 |

建议：**先使用 4 vCPU / 16 GB RAM / 100 GB SSD**。如果 Agent 与 Web 服务分开部署，Web 服务器可先用 4 vCPU / 8 GB。

## 2. 部署前检查

服务器需要安装：

- Git
- Docker
- Docker Compose
- 可访问 Docker Hub 或已配置可用的镜像源/私有 registry
- 域名和 HTTPS 证书（生产环境推荐）

先检查 Docker：

```bash
docker --version
docker compose version
docker pull python:3.12-slim
```

> 重要：当前 Dockerfile 依赖 `python:3.12-slim`。如果 `docker pull python:3.12-slim` 失败，`docker compose build` 也会失败，需要先配置 Docker 镜像加速、代理或私有 registry。

## 4. 配置环境变量

复制模板：

```bash
cp .env.example .env
```

编辑 `.env`，至少修改以下项：

```bash
# Database
POSTGRES_DB=bodiagent
POSTGRES_USER=bodiagent
POSTGRES_PASSWORD=<强密码>
POSTGRES_PORT_HOST=5432

# Redis
REDIS_PORT_HOST=6379

# Django
DJANGO_SECRET_KEY=<至少32字节的强随机密钥>
ALLOWED_HOSTS=你的域名,服务器IP
CORS_ALLOWED_ORIGINS=https://你的域名
CSRF_TRUSTED_ORIGINS=https://你的域名
WEB_PORT_HOST=8000
# ASGI 默认关闭 Django 持久连接，减少空闲 PostgreSQL 会话。
DB_CONN_MAX_AGE=0
# 单机自托管默认 2 个 Gunicorn worker；连接数充足后再调高。
WEB_CONCURRENCY=2

# 首次部署可开启自动迁移和静态文件收集
DJANGO_MIGRATE_ON_START=1
DJANGO_COLLECTSTATIC_ON_START=1

# 如果先用 HTTP/IP 测试，暂时关闭 HTTPS 强制跳转
SECURE_SSL_REDIRECT=false
SECURE_HSTS_SECONDS=0

# 生产使用 HTTPS 后再改为：
# SECURE_SSL_REDIRECT=true
# SECURE_HSTS_SECONDS=31536000
```

生成强随机密钥示例：

```bash
python3 - <<'PY'
import secrets
print(secrets.token_urlsafe(48))
PY
```

### 邮件和 Sentry

没有 SMTP/Sentry 凭据时，可先保留：

```bash
EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend
SENTRY_DSN=
```

生产正式上线前再配置 SMTP 和 Sentry。

## 5. 构建与启动

### 5.1 构建镜像

```bash
docker compose build
```

如果失败在：

```text
failed to resolve source metadata for docker.io/library/python:3.12-slim
connect: connection refused
```

说明服务器无法访问 Docker Hub。解决方式：

1. 配置 Docker 镜像加速器或代理；
2. 把 `python:3.12-slim` 同步到私有 registry；
3. 在可联网机器执行 `docker save`，拷贝到服务器 `docker load`。

离线导入示例：

```bash
# 可联网机器
docker pull python:3.12-slim
docker save python:3.12-slim -o python-3.12-slim.tar

# 服务器
docker load -i python-3.12-slim.tar
```

### 5.2 启动服务

```bash
docker compose up -d db redis web
```

查看状态：

```bash
docker compose ps
docker compose logs -f web
```

### 5.3 PostgreSQL 连接数建议

本项目生产镜像使用 ASGI（Gunicorn + Uvicorn）。Django 官方建议 ASGI 模式关闭持久数据库连接，因此默认：

```bash
DB_CONN_MAX_AGE=0
WEB_CONCURRENCY=2
```

如果出现 `remaining connection slots are reserved` 或 `too many clients already`：

1. 先确认 `.env` 中 `DB_CONN_MAX_AGE=0`，并降低 `WEB_CONCURRENCY`；
2. 重启 web 容器：`docker compose up -d --force-recreate web`；
3. 如需提高并发，优先增加 PostgreSQL `max_connections` 或引入 PgBouncer，再显式调高 `WEB_CONCURRENCY` / `DB_CONN_MAX_AGE`。

## 6. 初始化数据库和静态文件

如果 `.env` 中已设置：


```bash
docker compose exec -T web python manage.py migrate

```

检查迁移状态：

```bash
docker compose exec -T web python manage.py migrate --check
docker compose exec -T web python manage.py check
```

## 7. 创建管理员账号

当前系统使用**邮箱**登录，不是普通用户名登录。

创建默认演示管理员：

```bash
docker compose exec -T web python manage.py shell -c "from django.contrib.auth import get_user_model; U=get_user_model(); u,_=U.objects.get_or_create(email='admin@example.com', defaults={'name':'admin'}); u.set_password('admin123'); u.is_staff=True; u.is_superuser=True; u.save()"
```

登录信息：

- 邮箱：`admin@example.com`
- 密码：`admin123`
- 显示名：`admin`

> 生产上线后请立即修改默认密码，或创建新的管理员并删除演示账号。

## 9. Nginx / HTTPS / WebSocket

生产环境建议使用 Nginx 反向代理到 `web:8000` 或 `127.0.0.1:8000`。

关键点：`/ws/` 必须支持 WebSocket Upgrade，否则 Chat 和实时通道会断开。

示例：

```nginx
server {
    listen 80;
    server_name 你的域名;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name 你的域名;

    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location /ws/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location /static/ {
        alias /path/to/staticfiles/;
    }

    location /media/ {
        alias /path/to/media/;
    }
}
```

如果使用 Docker volume 保存静态文件，通常直接让 Django 容器服务静态文件也可用于早期部署；生产高流量时再把 volume 挂载到 Nginx。

## 10. Agent / Daemon 接入

Web 服务部署成功后，只代表平台可用；要让 AI Agent 接任务，还需要单独配置 daemon。

推荐：daemon 跑在开发机或独立 Agent 机器上，不一定要和 Web 服务器同机。

### 10.1 本机/Agent 机器准备

安装至少一个 AI CLI，例如 Claude Code：

```bash
which claude
claude --version
```

建议先跑最小测试：

```bash
claude -p "Reply with exactly: BODIAGENT_BARE_OK" \
  --bare --output-format stream-json --verbose \
  --max-budget-usd 0.20 --tools ''
```

### 10.2 生成 token 并配置 daemon

1. 浏览器登录 BodiAgent；
2. 进入 Settings → CLI Token；
3. 生成 token；
4. 在 Agent 机器上配置 daemon：

```bash
cd bodiagent/daemon_cli
python3 -m pip install -e .
bodiagent-daemon setup
```

填写：

- Server URL：`https://你的域名`
- Token：Web 端生成的 CLI Token
- Workspace：目标工作区

启动：

```bash
bodiagent-daemon start --foreground
```

### 10.3 浏览器创建 Agent 和任务

1. 在 Web 端创建/选择 Workspace；
2. 创建 Agent，provider 选择 `claude`；
3. 创建 Project；
4. 创建 Issue，把负责人设为该 Agent；
5. daemon 应拉取任务并提交消息/结果；
6. 在 Issue 详情页确认 Agent 输出和状态。

## 12. 常见问题

### 12.1 `docker compose build` 卡在 Docker Hub

现象：

```text
failed to resolve source metadata for docker.io/library/python:3.12-slim
connect: connection refused
```

原因：服务器无法访问 Docker Hub registry。

解决：配置镜像加速/代理、使用私有 registry，或离线导入 `python:3.12-slim`。

### 12.2 页面能打开，但 Chat/WebSocket 断开

检查 Nginx `/ws/` 是否配置：

```nginx
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

同时确认生产环境 Redis 可用。

### 12.3 登录 `admin/admin123` 失败

当前系统使用邮箱登录。请使用：

```text
admin@example.com / admin123
```

### 12.4 Agent 不接任务

检查：

- daemon 是否启动；
- daemon token 是否正确；
- daemon 是否绑定正确 workspace；
- Agent 是否绑定在线 daemon；
- 本机 `claude --version` 是否正常；
- Issue 是否已分配给 Agent。

### 12.5 生产环境强制 HTTPS 后本地健康检查失败

如果 `.env` 设置了：

```bash
SECURE_SSL_REDIRECT=true
```

HTTP 访问会跳转 HTTPS。早期部署验证可以先设为：

```bash
SECURE_SSL_REDIRECT=false
SECURE_HSTS_SECONDS=0
```

域名和证书配置完成后再开启。

## 13. 运维建议

- PostgreSQL 数据卷必须定期备份。
- `.env` 不要提交到 Git。
- `DJANGO_SECRET_KEY`、数据库密码、CLI Token 泄露后必须立即轮换。
- Docker 镜像建议固定 tag，避免基础镜像漂移。
- 正式生产建议拆分 Web、PostgreSQL、Redis、Agent 机器。
- Agent 任务可能执行代码和访问仓库，建议使用独立低权限用户运行 daemon。
